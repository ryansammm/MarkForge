# nested-pages Specification

## Purpose

Specifies how MarkForge models nested pages (page-in-page), how the
sidebar and the body render the hierarchy, and how `Turn into page`
creates child pages from a paragraph selection.

## Requirements

### Requirement: parent_id in the index

Every document in the workspace index SHALL carry a `parent_id` field
holding the path of the parent document, or `null` for a root
document. The index SHALL be rebuildable from the workspace at any
time.

#### Scenario: Root document

- **WHEN** a document has no `parent:` in its frontmatter
- **THEN** its `parent_id` in the index is `null`

#### Scenario: Child document

- **WHEN** a document has `parent: "folder/note.md"` in its
  frontmatter
- **THEN** its `parent_id` in the index is `"folder/note.md"`

### Requirement: Sidebar tree view

The sidebar SHALL render a collapsible tree of documents grouped
by `parent_id`, above the existing flat document list. Each node
displays the document title; clicking a node navigates to the
document. The tree state (which nodes are expanded) SHALL
persist across reloads via `localStorage`.

#### Scenario: Collapse and expand

- **WHEN** the user clicks a parent node
- **THEN** the children expand or collapse; the new state is
  saved

### Requirement: Breadcrumb

The editor SHALL render a breadcrumb above the document title
showing the chain of ancestors from the current document to the
root. Clicking any segment navigates to that document.

#### Scenario: Three-level nesting

- **WHEN** the active document has `parent_id = "A"` and
  `A` has `parent_id = "Root"`
- **THEN** the breadcrumb reads `Root / A / Current`

### Requirement: Turn into page

The block menu SHALL expose a `Turn into page` action in the
`Turn into` submenu. When the user invokes it on a non-empty
selection:

- A new child document is created at `<parent-dir>/<slug>.md`
  where `<slug>` is the first non-empty line of the selection
  (or `untitled` if empty).
- The new document's body is `## <title>\n\n<selection>`.
- The new document's `parent_id` is the active document's path.
- The parent document's body replaces the selection with
  `[[embed:<child-path>]]`.
- The index is refreshed.
- A toast appears with an `Open` action that opens the child
  in a new tab.

#### Scenario: Turn a paragraph into a page

- **WHEN** the user selects one paragraph in a document and
  invokes `Turn into page`
- **THEN** a new child document appears in the sidebar under
  the parent, the parent body shows an embed link, and the
  child body starts with the selected text

### Requirement: Child pages section in body

The reading view of a document SHALL render an auto-generated
`## Child pages` section at the bottom of the body, listing links
to each child whose `parent_id` matches. The section SHALL be
generated by the renderer from the index, not stored in the
document body.

#### Scenario: Parent with two children

- **WHEN** a document has two children
- **THEN** the reading view appends `## Child pages` with two
  links at the bottom of the body

#### Scenario: Edit mode hides the section

- **WHEN** the editor is in edit mode
- **THEN** the `## Child pages` section is not rendered
  (avoid visual clutter while typing)
